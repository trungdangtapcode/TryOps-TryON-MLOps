# Observability Contract

Date: 2026-06-11

## Implemented Local Signals

TryOps now has dependency-free API telemetry in `src/tryops/observability.py`.

Tracked per API observation:

- endpoint
- request ID
- workload
- safe model alias
- model version when available
- status
- request latency in milliseconds
- LLM tokens/sec when available
- LLM prefill and decode timing when available
- process memory in GB
- sanitized payload metadata
- quota-safe user hash and plan when supplied
- async VTON queue depth
- structured JSONL application logs
- OpenTelemetry-compatible trace IDs, span IDs, traceparent propagation, and local JSONL spans
- latency and quality alert threshold checks
- local image metadata and prompt/topic drift reports
- LLM guardrail findings by OWASP risk and action
- LLM semantic-cache hit/miss counters and saved cost/energy estimates

## Privacy Boundary

Telemetry must not store raw prompts, person image paths, garment image paths, or uploaded content.

Allowed payload metadata:

- LLM prompt character count
- max token request
- workload
- safe model alias
- routing mode
- shadow-mode flag
- fallback flag when present in routing metadata
- quota plan
- hashed user ID
- image field count
- output-path presence flag

The local implementation is intentionally simple so tests can run without Prometheus. The metric

The Rust gateway also exposes Prometheus-compatible text at `GET /metrics`:

- `tryops_gateway_requests_total`
- `tryops_gateway_request_latency_ms_bucket`

- `tryops_gateway_upstream_errors_total`
- `tryops_gateway_proxy_inflight`

The gateway metrics are emitted by the compiled Axum process, so Prometheus can scrape the
production edge directly instead of inferring edge behavior from Python logs.

## Structured Logs

API observations emit local JSONL records to `artifacts/logs/api_events.jsonl` by default. The shape
is inspired by the OpenTelemetry logs data model:

- `timestamp`
- `observed_timestamp`
- `severity_text`
- `severity_number`
- `event_name`
- `body`
- `resource`
- `attributes`

The log attributes contain sanitized request metadata, model alias, model version, status, latency,
memory, tokens/sec when available, LLM prefill/decode phase timing when available, and error code
when present. They must not contain raw prompts, image paths, or raw customer user IDs.

Set `TRYOPS_STRUCTURED_LOG_PATH` to redirect the JSONL sink in deployed environments. Production
should ship these records through OpenTelemetry Collector, Fluent Bit, or Grafana Alloy into Loki or
another log backend.

Research basis:

- OpenTelemetry logs data model: https://opentelemetry.io/docs/specs/otel/logs/data-model/
- Grafana Loki structured metadata: https://grafana.com/docs/loki/latest/get-started/labels/structured-metadata/

## Trace Spans

API observations emit local OpenTelemetry-compatible server spans to
`artifacts/traces/api_spans.jsonl` by default. Set `TRYOPS_TRACE_SPAN_PATH` to redirect the sink, or
call `configure_trace_span_path(None)` in a production process that exports through the
OpenTelemetry SDK directly.

Span records use `tryops.trace_span.v1` and include:

- W3C-compatible `traceparent`
- `trace_id`
- `span_id`
- optional upstream `parent_span_id`
- low-cardinality HTTP attributes such as `http.request.method` and `http.route`
- service resource fields
- request ID, workload, model alias, model version, quota plan, and hashed user ID
- LLM prefill/decode phase timing when present

The Rust gateway accepts incoming W3C `traceparent`, creates a gateway child span ID for proxied
requests, forwards the resulting header to the backend, and returns both `traceparent` and
`x-tryops-trace-id` on proxied responses. `make native-rust-smoke` verifies this gateway-level
propagation. Full production stitching still needs the OTLP exporter/Collector path.

Local evidence is generated by:

```bash
make trace-sample
```

Artifacts:

- `artifacts/eval/traces/trace_sample.json`
- `artifacts/eval/traces/api_spans.jsonl`
- `artifacts/eval/traces/api_events.jsonl`

Research basis:

- OpenTelemetry Trace API: https://opentelemetry.io/docs/specs/otel/trace/api/
- OpenTelemetry HTTP span semantic conventions: https://opentelemetry.io/docs/specs/semconv/http/http-spans/
- OpenTelemetry Protocol: https://opentelemetry.io/docs/specs/otlp/

## Quota Signals

Quota decisions are returned in API responses and can be joined with sanitized request telemetry by
`user_hash`, workload, model alias, and period. `make finops-sample` turns quota and benchmark
evidence into `tryops.unit_economics.v1` and `tryops.budget_showback.v1` artifacts. The API also
emits semantic-cache hit/savings counters when `/v1/llm/generate` serves repeated prompts from the
cache.

The production metrics contract includes:

- quota accepted and rejected request counts
- remaining daily token and request capacity bands
- high-usage tenant alerts by hashed tenant key
- plan-level utilization and upgrade pressure
- tenant budget utilization through `tryops_budget_utilization_ratio`
- cache hit rate through `tryops_semantic_cache_requests_total`
- cache cost/energy savings through `tryops_semantic_cache_savings_total`

route notifications through Alertmanager.

## Grafana Dashboards

Local Grafana provisioning is wired through:

- `infra/grafana/provisioning/datasources/prometheus.yml`
- `infra/grafana/provisioning/dashboards/tryops.yml`
- `infra/grafana/dashboards/tryops-service-overview.json`
- `infra/grafana/dashboards/tryops-model-quality.json`
- `infra/grafana/dashboards/tryops-cost-capacity.json`
- `infra/grafana/dashboards/tryops-guardrails.json`

The local Compose stack mounts `infra/grafana/dashboards` to `/var/lib/grafana/dashboards`.
Dashboard JSON targets use the stable Prometheus datasource UID `prometheus`.

Validation:

```bash
make dashboard-sample
```

The service dashboard uses live local API metrics. The model-quality and cost/capacity dashboards
reserve production metric names for release evidence, quota, and model-quality exporters; until
those exporters are live, their panels document the intended enterprise telemetry contract.

The guardrail dashboard targets `tryops_guardrail_events_total` and groups blocked/redacted/reviewed
findings by OWASP LLM 2025 risk ID. Local evidence is generated by:

```bash
make guardrail-sample
```

Prometheus also scrapes the native Go guardrail sidecar at `guardrail:18083`, which exposes
`tryops_native_guardrail_requests_total` and `tryops_native_guardrail_findings_total`.
When the Rust gateway is configured with `TRYOPS_GATEWAY_GUARDRAIL_URL`, it also emits
`tryops_gateway_guardrail_decisions_total{status="passed|blocked|error"}` for edge safety decisions.
The gateway also emits `tryops_gateway_semantic_cache_admissions_total{admitted,reason}` so cacheable
LLM prompts and privacy/sensitive skips are visible before FastAPI handles generation.

The cost/capacity dashboard now includes semantic-cache hit rate, cache cost savings, and budget
utilization panels. Local evidence is generated by:

```bash
make finops-sample
```

Artifacts:

- `artifacts/eval/finops/finops_report.json`

## Drift Reports

Local drift evidence is generated by:

```bash
make drift-sample
```

Artifacts:

- `artifacts/eval/drift/image_metadata_drift.json`
- `artifacts/eval/drift/prompt_topic_drift.json`
- `artifacts/eval/drift/drift_summary.json`

The VTON report compares image metadata descriptors such as width, height, aspect ratio, pixel
count, file size, role, format, and color mode. The LLM report compares prompt descriptors such as
character length, estimated token length, expected-check count, and deterministic topic category.

The reports store aggregate statistics and category counts only. They do not write raw prompt text,
uploaded image paths, user IDs, or image bytes.

Research basis:

- Evidently data drift explainer: https://docs.evidentlyai.com/metrics/explainer_drift
- Evidently text descriptors: https://docs.evidentlyai.com/docs/library/descriptors

## Current Gaps

- OpenTelemetry Collector wiring now exists through `infra/otel/collector.yml`, `docker-compose.yml`,
  and `make native-observability-contract-sample`; live OTLP exporters from every runtime under
  sustained load are still pending.
- No external durable log backend yet.
- GPU memory telemetry now exists through `make native-runtime-telemetry-sample`; per-request model
  VRAM attribution still needs live exporter integration.
- LLM phase timing for the deterministic baseline is a contract-level phase split; Transformers
  currently exposes a prompt-preparation plus `model.generate` proxy until vLLM/native tracing lands.
- No distributed multi-gateway quota admission validation yet; the Rust gateway has optional local
  file durability plus Postgres/Valkey-compatible quota mirrors and hashed tenant snapshots.
- Full live exporters for model-quality and some cost/capacity dashboard metrics are not wired yet.
- Drift reports use deterministic local sample windows, not production request windows yet.
- Chaos evidence is deterministic and local; production still needs controlled Chaos Mesh or
  LitmusChaos experiments against Kubernetes staging traffic.
- Async queue-depth telemetry is local in-process only; production needs queue and controller metrics.
- VTON stage-level timings are only available through the VTON report, not split by preprocessing
  sub-stage.
